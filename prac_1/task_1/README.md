# Учебный эмулятор командной оболочки

Проект реализует учебную UNIX-подобную консоль на Python 3. Команды выполняются над виртуальной файловой системой (VFS), которая загружается из JSON. Это эмулятор: он не выполняет команды операционной системы и не меняет реальные файлы при работе с содержимым VFS.

Изменения в VFS хранятся в памяти до завершения программы. Чтобы записать текущее состояние в JSON, используйте `vfs-save`.

Используются стандартная библиотека Python и модули самого проекта; устанавливать сторонние пакеты не требуется.

## Используемые библиотеки и модули

Внешние зависимости отсутствуют. Все перечисленные ниже библиотеки входят в стандартную поставку Python 3.

| Библиотека или модуль | Назначение |
|---|---|
| `argparse` | Разбор аргументов командной строки (`--vfs`, `--script`). |
| `json` | Чтение и запись JSON-представления виртуальной файловой системы. |
| `pathlib` (`Path`) | Представление и обработка путей к файлам и каталогам, проверка существования файлов. |
| `copy` | Глубокое копирование дерева VFS для изоляции начального состояния и сброса системы. |
| `shlex` | Разбиение введённой строки на токены с учётом кавычек и пробелов в аргументах. |
| `sys` | Доступ к стандартным потокам ввода и вывода, а также передача кода завершения процесса. |
| `enum` (`Enum`) | Определение именованных статусов выполнения команды. |
| `collections.abc` (`Sequence`) | Аннотация типа последовательности аргументов команды. |
| `typing` (`Any`, `Sequence`, `TextIO`) | Аннотации типов для данных JSON, последовательностей и текстовых потоков. |
| `unittest` | Реализация автоматических модульных тестов. |
| `unittest.mock` (`patch`) | Подмена объектов и поведения зависимостей в тестах. |
| `io` | Создание тестовых потоков ввода и вывода в памяти. |
| `tempfile` | Создание временных файлов и каталогов для изолированных тестов. |

Кроме стандартных библиотек приложение использует собственные модули проекта: `config` (параметры запуска), `command_parser` (разбор команд), `commands` (их выполнение), `filesystem` (операции с VFS) и `shell` (интерактивный режим и сценарии). Эти модули не являются внешними пакетами.

## Запуск

Все команды ниже выполняются из папки `task_1`.

### Интерактивный режим

```bash
python3 main.py
```

Для запуска со стандартной VFS есть скрипт:

```bash
./scripts/run_interactive.sh
```

Появится приглашение вида `vfs:/$`. Вводите команды эмулятора по одной строке. Для выхода введите `exit` или завершите ввод EOF (`Ctrl+D` в Linux/macOS).

### Запуск с указанной VFS или сценарием

```bash
python3 main.py --vfs data/vfs_sample.json
python3 main.py --vfs data/vfs_sample.json --script scripts/demo_basic_commands.txt
```

`--vfs` задаёт JSON-файл виртуальной файловой системы, а `--script` — файл со стартовыми командами (по одной на строку). После успешного выполнения сценария программа переходит в интерактивный режим, если сценарий не завершил её командой `exit`.

Примеры файлов VFS: `vfs.json` (пустая VFS), `data/vfs_minimal.json`, `data/vfs_sample.json`, `data/vfs_nested.json`.

### Демонстрационные сценарии

```bash
./scripts/run_demo.sh
./scripts/run_basic_commands.sh
./scripts/run_file_operations.sh
./scripts/run_sample_vfs.sh
./scripts/run_nested_vfs.sh
```

Скрипты запуска находятся в `scripts/`, а команды для эмулятора — в соответствующих `demo*.txt`.

### Тесты

```bash
python3 -m unittest discover -s tests -v
```

Тесты используют только стандартный модуль `unittest`.

## Команды консоли

Пути относятся к VFS, а не к файловой системе компьютера. Относительные пути задаются от текущей виртуальной директории. Кавычки позволяют передавать аргументы с пробелами, например `ls "my folder"`.

| Команда | Назначение и формат |
|---|---|
| `ls [ПУТЬ]` | Показывает содержимое директории. Без пути показывает текущую директорию. |
| `cd [ПУТЬ]` | Переходит в директорию. Без пути переходит в корень VFS (`/`). |
| `pwd` | Показывает путь текущей директории. |
| `uniq ПУТЬ_К_ФАЙЛУ` | Выводит содержимое файла, убирая соседние одинаковые строки. Исходный файл не изменяется. |
| `cp ИСХОДНЫЙ_ФАЙЛ НАЗНАЧЕНИЕ` | Копирует файл в VFS. Назначением может быть путь нового файла или существующая директория. |
| `chown ВЛАДЕЛЕЦ ПУТЬ` | Меняет владельца файла или директории в VFS. |
| `clear` | Очищает экран в интерактивном терминале. |
| `vfs-save ПУТЬ` | Сохраняет текущее дерево VFS в указанный JSON-файл. |
| `vfs-init` | Сбрасывает VFS в памяти к начальному содержимому `vfs.json` проекта. Текущий JSON-файл автоматически не перезаписывается. |
| `exit` | Завершает интерактивную оболочку или останавливает сценарий. |

Аргументы в квадратных скобках необязательны. Имена команд чувствительны к регистру. Неизвестные команды не запускаются как команды ОС.

## Ошибки и предупреждения

При ошибке в интерактивном режиме выводится сообщение, после чего можно вводить следующую команду. При ошибке команды в стартовом сценарии выполнение сценария останавливается; интерактивный режим после такого сценария не запускается.

### Ввод команды

| Сообщение | Причина и решение |
|---|---|
| `Ошибка: незакрытая кавычка` | В строке команды открыта, но не закрыта одинарная или двойная кавычка. Закройте кавычку или удалите её. |
| `Ошибка: неизвестная команда: ИМЯ` | Команды с таким именем нет среди реализованных. Проверьте написание; поддерживаемые команды перечислены выше. |
| `Ошибка: использование: ...` | Команда получила неверное количество аргументов. Используйте формат, показанный в сообщении. |

Для `clear` также могут появиться системные сообщения `argparse` об ошибке параметров запуска, например о неизвестном параметре или пропущенном значении после `--vfs`/`--script`. Они возникают до запуска оболочки; проверьте параметры и запустите программу снова.

### Ошибки команд и виртуальных путей

| Сообщение | Причина и решение |
|---|---|
| `Ошибка: VFS не загружена` | Команде нужна виртуальная файловая система, но она не была передана оболочке. При обычном запуске через `main.py` VFS загружается автоматически. |
| `Ошибка: путь не найден: ПУТЬ` | Указанный путь или один из его элементов отсутствует в VFS. Проверьте путь через `ls` и `pwd`. |
| `Ошибка: нельзя перейти выше корня VFS` | Путь с `..` пытается подняться выше `/`. Используйте корректный путь внутри VFS. |
| `Ошибка: это не директория: ПУТЬ` | Для `cd`, `ls` или каталога назначения в `cp` указан файл либо путь не является директорией. |
| `Ошибка: это не файл: ПУТЬ` | В `uniq` передан каталог вместо файла. |
| `Ошибка: исходный объект не является файлом: ПУТЬ` | В качестве источника `cp` указан каталог. Копирование каталогов не поддерживается. |
| `Ошибка: не указан путь назначения` | `cp` получил пустое назначение. Укажите путь файла или директорию назначения. |
| `Ошибка: недопустимый путь назначения: ПУТЬ` | Путь назначения `cp` пуст либо его конечное имя некорректно (например, `.` или `..`). Укажите имя нового файла. |
| `Ошибка: объект уже существует: ПУТЬ` | В месте назначения уже есть файл с таким именем. Выберите другое имя; перезапись не выполняется. |
| `Ошибка: владелец не может быть пустым` | В `chown` передано пустое имя владельца. Укажите непустое значение. |

`ls` должен получить корневую директорию или другой каталог; `uniq` — существующий файл. Для `cp` родительская директория назначения должна существовать.

### Запуск, VFS и стартовый сценарий

| Сообщение | Причина и решение |
|---|---|
| `Ошибка: файл VFS не найден: ПУТЬ` | Файл из `--vfs` (или стандартный `vfs.json`) не найден. Проверьте путь и текущую конфигурацию проекта. |
| `Ошибка: стартовый скрипт не найден: ПУТЬ` | Файл из `--script` отсутствует. Проверьте путь к сценарию. |
| `Ошибка: файл VFS не найден: ПУТЬ` | VFS не удалось открыть, прочитать или разобрать как JSON. Сообщение может содержать системную причину; проверьте доступ и корректность JSON. |
| `Ошибка: не удалось прочитать VFS ПУТЬ: ...` | Файл VFS недоступен, содержит некорректный JSON или не читается в UTF-8. Исправьте JSON, кодировку или права доступа. |
| `Ошибка: ...` с описанием объекта/поля | JSON прочитан, но структура VFS не соответствует схеме. Корень и каталоги должны быть объектами типа `directory` с полями `name`, `type`, `owner`, `children`; файлы должны иметь строковое поле `content`. Имена дочерних объектов должны быть допустимыми, а имя объекта — соответствовать его ключу. |
| `Ошибка: не удалось открыть стартовый скрипт: ...` | Сценарий невозможно открыть. Проверьте путь, права доступа и кодировку UTF-8. |
| `Ошибка: не удалось прочитать стартовый скрипт: ...` | Во время чтения сценария возникла ошибка ввода-вывода или кодировки. Проверьте файл и его кодировку UTF-8. |
| `Ошибка: не удалось сохранить VFS в ПУТЬ: ...` | Не удалось записать JSON: например, каталог назначения отсутствует или нет прав на запись. Укажите доступный путь. |

При проверке структуры VFS конкретная причина уточняется в сообщении. Возможные причины включают: корень не является объектом или директорией, корень назван не `/`, у объекта отсутствует `name`, `type` или `owner`, имя не совпадает с ключом, владелец не строка, у файла нет строкового `content`, у директории нет объекта `children`, указан неизвестный тип объекта или недопустимое имя дочернего элемента.

### Предупреждения

| Сообщение | Значение |
|---|---|
| `Предупреждение: не удалось очистить экран: ...` | Терминал не смог обработать команду очистки экрана. Это не останавливает эмулятор; очистка выполняется только при выводе в интерактивный терминал. |

## Структура проекта

| Файл/папка | Назначение |
|---|---|

| `tests/` | Автоматические тесты. |
| `data/` | Примеры JSON-файлов VFS. |
| `scripts/` | Сценарии команд и скрипты запуска. |
