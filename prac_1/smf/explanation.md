# Разбор практической работы №1

Этот конспект разбирает команды из [`task_1.txt`](task_1.txt): что делает каждая часть, как передаются данные между командами и что важно уметь объяснить на защите. Лучше не заучивать текст дословно: попробуй самостоятельно запустить команды и пересказать их смысл.

## Основы командной строки

Команда обычно состоит из имени программы, параметров и аргументов:

```text
программа параметры аргументы
```

Например, в `head -n 5 файл.txt` программа `head` получает параметр `-n 5` и имя файла `файл.txt`.

- **Аргумент** сообщает программе, с чем работать: например, имя файла или каталога.
- **Параметр** меняет поведение программы: например, `-n 5` просит вывести пять строк.
- **Путь** указывает расположение файла. `.` означает текущий каталог, `/etc/passwd` — абсолютный путь от корня файловой системы.
- **Кавычки** вокруг `"$file"` сохраняют значение переменной одним аргументом, даже если в имени есть пробелы.
- **Переменная** хранит значение. В Bash для чтения переменной ставится `$`: например, `$1` — первый аргумент скрипта.
- **Конвейер `|`** передаёт вывод одной команды на вход следующей.
- **Перенаправление `>`** направляет вывод в файл. Оно создаёт файл или очищает уже существующий.
- **Код завершения** сообщает об успехе или ошибке. Обычно `0` означает успех, ненулевое значение — ошибку. `exit 1` завершает скрипт с ошибкой.
- **`stdout` и `stderr`** — обычный вывод программы и поток сообщений об ошибках. Запись `>&2` отправляет сообщение в `stderr`.

Строка `#!/bin/bash` в начале скрипта называется shebang: она указывает системе, что файл нужно выполнять Bash. Чтобы запускать файл как программу, ему обычно дают право на выполнение, например `chmod +x имя_скрипта`, затем запускают `./имя_скрипта`.

## Задание 1. Имена пользователей

```bash
grep -o "^[^:]*" /etc/passwd | sort
```

Файл `/etc/passwd` хранит сведения об учётных записях; поля разделены двоеточиями. Первое поле — имя пользователя.

- `grep` ищет строки по шаблону.
- `-o` выводит только совпавшую часть строки, а не всю строку.
- `^` означает начало строки.
- `[^:]*` означает «ноль или больше символов, кроме `:`». Поэтому совпадает первое поле до двоеточия.
- `/etc/passwd` — файл, который читается.
- `| sort` передаёт найденные имена программе `sort`, которая сортирует строки по алфавиту.

**Идея:** взять начало каждой строки до первого разделителя и отсортировать получившиеся имена.

## Задание 2. Пять наибольших номеров протоколов

```bash
cat /etc/protocols | sort -k2 -nr | head -5 | awk '{print $2, $1}'
```

В `/etc/protocols` обычно сначала указано имя протокола, затем его номер, затем возможные псевдонимы. Задание в тексте называет эти числа портами, но точнее говорить **номера протоколов**: это именно содержимое файла `/etc/protocols`.

1. `cat /etc/protocols` выводит файл.
2. `sort -k2 -nr` сортирует строки по второму полю (`-k2`), численно (`-n`) и в обратном порядке (`-r`), то есть от большего числа к меньшему.
3. `head -5` оставляет первые пять строк.
4. `awk '{print $2, $1}'` печатает второе поле, затем первое: сначала номер, потом имя, как в примере задания.

Кавычки вокруг программы `awk` важны: они не дают оболочке преждевременно обработать `$2` и `$1`. Эти обозначения относятся к полям строки внутри `awk`.

`cat` здесь можно было бы убрать и передать имя файла прямо в `sort`, но текущий вариант наглядно показывает передачу данных по конвейеру.

## Задание 3. Рамка вокруг текста

```bash
#!/bin/bash

length=${#1}

printf '+%*s+\n' "$((length + 2))" '' | tr ' ' '-'
printf '| %s |\n' "$1"
printf '+%*s+\n' "$((length + 2))" '' | tr ' ' '-'
```

Скрипт получает текст первым аргументом. Например: `./banner "Hello from RTU MIREA!"`. Кавычки нужны, чтобы фраза с пробелами стала одним аргументом.

- `${#1}` — длина первого аргумента; результат сохраняется в переменную `length`.
- `$((length + 2))` — арифметическое выражение Bash. Два дополнительных символа нужны для пробелов по бокам текста.
- `printf` форматирует вывод. В `'+%*s+\n'` символ `%*s` означает строковое поле с шириной, переданной следующим аргументом. Здесь строка пустая, поэтому поле заполняется пробелами.
- `tr ' ' '-'` заменяет пробелы в этой строке на дефисы, получая верхнюю или нижнюю границу.
- `printf '| %s |\n' "$1"` выводит текст между вертикальными линиями. `%s` — место для строки, `\n` — перевод строки.

Использован `printf`, а не `echo`: `printf` предсказуемо печатает текст, даже если он начинается, например, с `-n`.

## Задание 4. Поиск идентификаторов

```bash
grep -oE '[a-zA-Z_][a-zA-Z0-9_]*' hello.c | sort -u
```

Шаблон описывает упрощённое правило идентификатора C-подобных языков:

- `[a-zA-Z_]` — первый символ: латинская буква или подчёркивание.
- `[a-zA-Z0-9_]*` — после первого символа может идти ноль или больше латинских букв, цифр или подчёркиваний.
- `grep -E` включает расширенные регулярные выражения, а `-o` выводит каждое совпадение отдельно.
- `sort -u` сортирует найденные строки и оставляет только уникальные (`-u`).

**Ограничение:** это поиск по тексту, а не полноценный разбор языка компилятором. Он может найти слова внутри комментариев и строк, а правило покрывает ASCII-буквы, но не все возможные правила идентификаторов разных языков.

## Задание 5. Установка команды

```bash
#!/bin/bash

chmod +x -- "$1"
sudo install -m 755 -- "$1" /usr/local/bin/
```

Пример запуска: `./reg banner`, если файл `banner` находится в текущем каталоге.

- `$1` — путь, переданный скрипту первым аргументом.
- `chmod +x` добавляет файлу право на выполнение.
- `--` означает конец параметров команды. Это помогает, если имя файла начинается с дефиса.
- `sudo` запускает следующую команду с правами администратора: запись в `/usr/local/bin` обычно требует таких прав.
- `install -m 755` копирует файл в указанное место и задаёт режим доступа `755`: владелец может читать, изменять и запускать файл; группа и остальные пользователи могут читать и запускать его.
- `/usr/local/bin` — обычное место для локально установленных команд; часто этот каталог уже входит в переменную поиска команд `PATH`.

`chmod` меняет права исходного файла, а `install -m 755` при копировании явно задаёт права установленной копии. После успешной установки команду обычно можно найти через `command -v banner`.

## Задание 6. Комментарий в первой строке

```bash
#!/bin/bash

find . -maxdepth 1 -type f \( -name '*.c' -o -name '*.js' -o -name '*.py' \) -print0 |
while IFS= read -r -d '' file; do
    first_line=$(head -n 1 "$file")

    extension="${file##*.}"

    if [[ "$extension" == "py" && "$first_line" =~ ^[[:space:]]*# ]] ||
        [[ "$extension" != "py" && "$first_line" =~ ^[[:space:]]*(//|/\*) ]]; then
        echo "$file: первая строка содержит комментарий"
    else
        echo "$file: первая строка не содержит комментарий"
    fi
done
```

- `find .` ищет от текущего каталога.
- `-maxdepth 1` ограничивает поиск самим каталогом, не заходя во вложенные.
- `-type f` выбирает обычные файлы.
- `\(` и `\)` группируют условия поиска, а `-o` означает «или». Так выбираются расширения `.c`, `.js` и `.py`.
- `-print0` разделяет найденные имена нулевым байтом. Это надёжнее перевода строки: в имени файла могут быть пробелы и даже переводы строк.
- `while ... read` читает по одному имени. `IFS=` не обрезает пробелы в начале и конце, `-r` сохраняет обратные слеши, `-d ''` задаёт нулевой байт как разделитель в Bash.
- `head -n 1` берёт первую строку файла.
- `${file##*.}` удаляет из имени всё до последней точки; остаётся расширение.
- `[[ ... ]]` — условие Bash. `&&` означает «и», `||` — «или», `=~` проверяет соответствие регулярному выражению.
- `[[:space:]]*` допускает пробелы в начале строки. Для Python ищется `#`, для C и JavaScript — `//` или `/*`.

Логика условия: **либо** расширение Python и первая строка начинается с `#`, **либо** расширение не Python и первая строка начинается с `//` или `/*`.

**Ограничения:** рассматривается только первая строка и только файлы непосредственно в текущем каталоге. Например, многострочный комментарий, начинающийся со второй строки, этот скрипт не найдёт. Строка Python с shebang (`#!/...`) тоже начинается с `#` и будет распознана как комментарий.

## Задание 7. Поиск дубликатов

```bash
#!/bin/bash
find "$1" -type f -exec sha256sum {} + | sort | uniq -w 64 -D
```

Скрипт получает каталог первым аргументом и ищет файлы также во вложенных каталогах.

- `find "$1" -type f` находит обычные файлы под указанным путём.
- `-exec sha256sum {} +` запускает `sha256sum` для найденных файлов группами. `{}` заменяется именами файлов, а `+` позволяет передавать несколько файлов за один запуск.
- `sha256sum` вычисляет контрольную сумму содержимого. У одинакового содержимого будет одинаковая сумма.
- `sort` группирует строки с одинаковыми суммами рядом.
- `uniq -w 64 -D` сравнивает первые 64 символа строки (64 шестнадцатеричных символа SHA-256) и выводит все строки из повторяющихся групп.

Так скрипт печатает контрольные суммы и имена файлов, у которых совпало содержимое. Это сравнение по хешу: вероятность случайной коллизии SHA-256 крайне мала, но теоретически хеш не является математическим доказательством равенства файлов. Вариант использует утилиты GNU/Linux.

## Задание 8. Архивирование файлов по расширению

```bash
#!/bin/bash

if [[ $# -ne 2 ]]; then
    printf 'Использование: %s КАТАЛОГ РАСШИРЕНИЕ\n' "$0" >&2
    exit 1
fi

directory=$1
extension=${2#.}

if [[ ! -d "$directory" || -z "$extension" || "$extension" == */* ]]; then
    printf 'Укажите существующий каталог и корректное расширение.\n' >&2
    exit 1
fi

archive="${extension}_files.tar"
mapfile -d '' files < <(
    cd -- "$directory" &&
    find . -type f -name "*.${extension}" ! -path "./${archive}" -print0
)

if [[ ${#files[@]} -eq 0 ]]; then
    printf 'Файлы с расширением .%s не найдены.\n' "$extension"
    exit 0
fi

tar -cf "$archive" -C "$directory" -- "${files[@]}"
```

Пример запуска: `./archive_ext каталог txt` или `./archive_ext каталог .txt`.

- `$#` — количество аргументов, `$0` — имя самого скрипта. Здесь требуется ровно два аргумента.
- `[[ ... ]]` проверяет условие; `-ne` означает «не равно», `-d` проверяет существование каталога.
- `${2#.}` удаляет одну начальную точку из второго аргумента, если она есть. Так принимаются и `txt`, и `.txt`.
- `archive` получает имя будущего архива, например `txt_files.tar`. Архив создаётся в текущем каталоге.
- `mapfile -d '' files` читает список имён в Bash-массив `files`, используя нулевой байт как разделитель.
- `< <(...)` — подстановка процесса Bash: команда внутри круглых скобок выдаёт список, который читает `mapfile`.
- `cd -- "$directory"` переходит в каталог; `&&` запускает `find` только если переход удался.
- `find . -type f -name "*.${extension}"` рекурсивно ищет обычные файлы с нужным суффиксом. Шаблон заключён в кавычки, чтобы его обрабатывал `find`, а не сама оболочка.
- `! -path "./${archive}"` не даёт включить в архив уже созданный архив, если он находится в просматриваемом каталоге.
- `${#files[@]}` — количество элементов массива. Если файлов нет, скрипт сообщает об этом и завершает работу.
- `tar -cf` создаёт tar-архив. `-C "$directory"` переключает `tar` в нужный каталог перед добавлением файлов; `--` отделяет параметры от имён файлов. Кавычки вокруг `"${files[@]}"` передают каждое имя отдельным аргументом.

Расширение в этом решении чувствительно к регистру: `.txt` и `.TXT` — разные варианты.

## Задание 9. Замена четырёх пробелов табуляцией

```bash
#!/bin/bash

if [[ $# -ne 2 ]]; then
    printf 'Использование: %s ВХОДНОЙ_ФАЙЛ ВЫХОДНОЙ_ФАЙЛ\n' "$0" >&2
    exit 1
fi

input=$1
output=$2

if [[ ! -r "$input" ]]; then
    printf 'Входной файл недоступен для чтения: %s\n' "$input" >&2
    exit 1
fi

if [[ "$input" == "$output" || ( -e "$output" && "$input" -ef "$output" ) ]]; then
    printf 'Входной и выходной файлы должны быть разными.\n' >&2
    exit 1
fi

sed 's/    /\t/g' -- "$input" > "$output"
```

Пример запуска: `./spaces_to_tabs input.txt output.txt`.

- Проверка `$# -ne 2` требует входной и выходной файлы.
- `-r` проверяет, доступен ли входной файл для чтения.
- Сравнение путей `"$input" == "$output"` запрещает одинаковые написания пути. Условие `-ef` дополнительно проверяет, не указывают ли два пути на один и тот же существующий файл.
- `sed` обрабатывает текст построчно. Выражение `s/    /\t/g` означает: заменить четыре пробела табуляцией (`\t` в GNU `sed`), а `g` применяет замену ко всем совпадениям в строке.
- `> "$output"` записывает результат в выходной файл. Если он уже существует, содержимое будет перезаписано.

Восемь подряд идущих пробелов заменятся двумя табуляциями: замены идут по неперекрывающимся группам по четыре пробела. Три пробела не заменятся.

## Задание 10. Поиск пустых файлов

```bash
#!/bin/bash

if [[ $# -ne 1 || ! -d "$1" ]]; then
    printf 'Использование: %s КАТАЛОГ\n' "$0" >&2
    exit 1
fi

find "$1" -maxdepth 1 -type f -empty -print
```

Пример запуска: `./empty_files каталог`.

- Скрипту требуется ровно один аргумент, и он должен быть каталогом. `||` означает «или»: при неверном числе аргументов **или** если путь не является каталогом, печатается подсказка.
- `find "$1"` ищет в переданном каталоге.
- `-maxdepth 1` не заходит во вложенные каталоги.
- `-type f` выбирает обычные файлы.
- `-empty` выбирает файлы нулевого размера.
- `-print` выводит пути найденных файлов.

Пустой файл не содержит байтов, по которым можно определить, был ли он задуман как текстовый или бинарный. Поэтому решение трактует пустые обычные файлы как пустые текстовые файлы.

## Подготовка к защите

Для каждого решения удобно отвечать по одной схеме: **что поступает на вход → какая обработка выполняется → что получается на выходе**.

1. **Почему в задании 1 нужен шаблон `^[^:]*`?** Он берёт символы от начала строки до первого двоеточия, то есть первое поле файла.
2. **Чем `sort -n` отличается от обычного `sort`?** Он сравнивает числа как числа, а не как текстовые строки.
3. **Зачем в banner используется `${#1}`?** Чтобы вычислить длину аргумента и подстроить ширину рамки.
4. **Что означает `sort -u`?** Отсортировать строки и убрать повторения.
5. **Зачем `sudo` в задании 5?** Для установки команды в системный каталог, куда обычному пользователю нельзя записывать.
6. **Зачем `-print0` и `read -d ''` в задании 6?** Чтобы имена с пробелами и специальными символами читались как одно имя файла.
7. **Как находятся дубликаты в задании 7?** Содержимое файлов преобразуется в хеши; одинаковые хеши группируются и выводятся вместе.
8. **Зачем в задании 8 массив `files`?** Он хранит найденные пути отдельными элементами, чтобы пробелы в именах не разбивали их на разные аргументы.
9. **Что делает `g` в выражении `sed`?** Разрешает заменить все подходящие последовательности в строке, а не только первую.
10. **Почему задание 10 использует `-maxdepth 1`?** Поиск ограничен указанным каталогом, без вложенных каталогов.

Перед защитой полезно самому запустить каждый скрипт на небольшом тестовом примере и попробовать изменить входные данные. Если можешь объяснить, почему меняется результат, значит, ты понимаешь решение, а не просто запомнил его.
